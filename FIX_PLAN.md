# План исправлений Pipeline

## Анализ текущей логики

### 1. snap_window_sec ограничение
- **Текущее**: жестко ограничено до 0.25 секунды
- **Защита уже есть**: в `silence_detect.py` есть `max_duration_change = window_sec * 2`
- **Вывод**: ограничение 0.25 избыточно, можно безопасно увеличить до 1.0-2.0

### 2. hook_first + boundary_mode конфликт
- **Текущее**: 
  - hook_first сдвигает `clip_start` (строка 518)
  - boundary_mode находит слова от нового `clip_start` (строка 529)
  - boundary_mode корректирует `clip_start` к `first_word["start"]` (строка 533)
- **Проблема**: если hook_first сдвинул начало назад (раньше), boundary_mode может сдвинуть вперед
- **Решение**: если hook_first использован, не применять boundary_mode для начала (только для конца)

### 3. Двойная корректировка boundary_mode
- **Текущее**: применяется дважды (строки 532-534 и 640-651)
- **Проблема**: избыточно, может конфликтовать с snapping
- **Решение**: убрать первую корректировку, оставить только после snapping

### 4. snapped_end >= segment["end"]
- **Текущее**: всегда >= оригинального конца
- **Проблема**: может оставлять лишнее аудио
- **Решение**: сделать условным - не применять если boundary_mode == "word"

### 5. Валидация
- **Текущее**: нет финальной проверки перед нарезкой
- **Решение**: добавить проверку start < end и минимальной длительности
