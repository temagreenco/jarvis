## ⚠️ Найденные проблемы

### 1. **КРИТИЧНО: snap_window_sec искусственно ограничен**

**Проблема:**
```python
# workers/worker.py:624
snap_window_sec = float(input_data.get("snap_window_sec", 1.0))
snap_window_sec = min(snap_window_sec, 0.25)  # ❌ Ограничение до 0.25 секунды!
```

**Влияние:**
- По умолчанию передается `snap_window_sec=1.0`, но он обрезается до 0.25 секунды
- Это делает snapping к тишине менее эффективным
- Может пропускать хорошие границы тишины, которые находятся дальше 0.25 секунды

**Решение:**
- Убрать ограничение или увеличить до разумного значения (например, 1.0-2.0 секунды)
- Или сделать это настраиваемым параметром

---

### 2. **Потенциальный конфликт: hook_first_cutting + boundary_mode word**

**Проблема:**
Порядок операций может конфликтовать:

1. **hook_first_cutting** сдвигает начало к hook (строка 518)
2. **boundary_mode == "word"** обрезает до границ первого слова (строки 532-534)
3. **snap_to_silence** сдвигает границы (строка 633)
4. **boundary_mode == "word"** снова корректирует snapped границы (строки 640-651)

**Сценарий проблемы:**
- hook_first_cutting находит hook на 2 секунде и сдвигает начало
- boundary_mode находит первое слово на 1.5 секунде и возвращает начало обратно
- Результат: hook_first_cutting не работает

**Решение:**
- Проверить логику: если hook_first_cutting сдвинул начало, не применять boundary_mode word для начала
- Или применять boundary_mode только если hook_first не использовался

---

### 3. **snapped_end всегда >= segment["end"]**

**Проблема:**
```python
# workers/worker.py:637-639
if task == "auto_clips":
    snapped["snapped_end"] = max(
        float(snapped["snapped_end"]), float(segment["end"])
    )
```

**Влияние:**
- Если snap_to_silence нашел тишину раньше конца сегмента, это игнорируется
- Может оставлять лишнее аудио в конце клипа
- Может конфликтовать с boundary_mode word, который хочет обрезать до последнего слова

**Решение:**
- Убрать это ограничение или сделать его условным
- Или применять только если не используется boundary_mode word

---

### 4. **Двойная корректировка boundary_mode word**

**Проблема:**
boundary_mode == "word" применяется дважды:
1. Строки 532-534: до snapping к тишине
2. Строки 640-651: после snapping к тишине

**Влияние:**
- Избыточная обработка
- Может конфликтовать с snapping к тишине
- Неясно, какая корректировка имеет приоритет

**Решение:**
- Применять boundary_mode word только один раз - после snapping к тишине
- Или четко определить приоритет операций

---

### 5. **Отсутствие валидации после всех корректировок**

**Проблема:**
После всех операций (hook_first, boundary_mode, snapping) нет финальной валидации:
- Проверка, что start < end
- Проверка минимальной длительности
- Проверка, что границы не выходят за пределы видео

**Решение:**
- Добавить финальную валидацию перед нарезкой
